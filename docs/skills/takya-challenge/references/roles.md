# Lentes del comité

Elegir los roles que cambian la decisión; no repetir seis veces el mismo hallazgo.

| Rol | Contraejemplo que debe intentar | Evidencia mínima |
| --- | --- | --- |
| Operador / UX | Entiende el icono pero decide sobre el caso equivocado; confía más pese a un fallo | Tarea observada, evidencia visible, errores, ayuda y reconocimiento del fallo |
| Data engineer | Un mismo video acaba en ajuste y evaluación; origen/hora no verificados | Inventario, hashes, partición por escena y procedencia de tiempos |
| ML / visión | 1 FPS pierde un cruce breve; menor número de alertas es menor recall | Eventos anotados, FN/FP por evento, negativos continuos y configuración congelada |
| Seguridad / evidencia | Sustituye video, manifiesto y clave pública juntos; accede a otra sesión | Referencia externa de confianza, tests de manipulación y permisos en streaming/exportación |
| Cloud / fiabilidad / FinOps | El demo web no alcanza el worker, reiniciar pierde decisiones o cola consume toda RAM | Topología real, identidad, límites, caída/cancelación, recursos y costo por carga |
| Negocio / CEO | Le gusta al usuario pero el comprador ya resuelve la tarea sin pagar | Comparación con proceso existente, responsable y compromiso de piloto con oferta concreta |
| Privacidad / receptor | El clip funciona pero no tiene permiso de difusión o el destinatario no acepta el paquete | Autorización, finalidad, procedimiento y aceptación real; sin presumir valor legal |

Preguntas transversales: ¿qué ocurrió realmente?, ¿qué se simuló?, ¿qué puede refutarlo?, ¿cuál es el alcance de la garantía? Una captura, un mock y un acceso autenticado son evidencias distintas.
